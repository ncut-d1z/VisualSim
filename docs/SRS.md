# VisualSim 运行时库需求分析（SRS）

> 状态：设计基线（计划阶段，仅文档）；目标仓库：ncut-d1z/VisualSim；来源仓库：ncut-d1z/ros2-vio-node。对应设计：HLD.md、LLD.md。
>
> 基线参考：目标仓库 main 941f05ce93cc197fab2cffafb9d597bf1f7809ba；来源仓库 main f1cb7a02587199ce2dfc588789f044ccae2945ed。后续实施前复核两仓库的新变更。

## 1. 项目目标与不可违背的约束

将 https://github.com/ncut-d1z/VisualSim 改造为 Ubuntu 24.04 下可安装、可链接、按请求生成仿真双目图像和 IMU 数据的**独立 C++ 共享运行时库**，保留适用的现有命令行数据集导出功能；同时提供解析轨迹、实时标定配置、传感器门控、图像位姿缓存及单位视线与场景真实表面求交能力。

**写入边界：仅允许修改 ncut-d1z/VisualSim。** https://github.com/ncut-d1z/ros2-vio-node/tree/main/src/VisualSim 仅允许读取并作为迁移来源；禁止向来源仓库提交、推送、创建 PR 或改写任何文件。迁移是在目标仓库中择优复用、整合、修正代码，不是直接替换整个项目。

- 核心库不得依赖 ROS、ROS 2、ament、rclcpp、sensor_msgs、cv_bridge、ROS 消息类型或 ROS 工作空间；允许 Eigen、Sophus、OpenCV、yaml-cpp 等与 ROS 无关的第三方库，且只链接实际使用的依赖。
- 唯一承诺的构建/运行目标是 **Ubuntu 24.04 / Linux**。目标仓库此后**禁止 Windows 平台构建**；应在 CMake 配置期明确拒绝 Windows，移除 Windows 专用构建入口和说明。其他 Linux 发行版不作兼容性承诺。
- **不得为了兼容 Ubuntu 自带软件包而强制降低 CMake、编译器、C++ 标准或依赖版本**。用户已有能构建两个仓库的工具链；基于实际项目需要选择并记录要求，而非发起降级任务。
- 用户此轮授权的是三份设计文档的写入；不修改生产代码、不运行构建、CTest 或仿真。后续代码实施另按文档执行。
- 除本文件另有明示，沿用既有方案建议：Linux .so、CMAKE_INSTALL_PREFIX、CMake package、左右目同步门控、独立传感器编号、最近 64 组双目缓存、默认 cam0 查询、射线与有限表面解析求交、IMU 噪声默认关闭但可真实启用及固定种子、保留命令行导出能力。

## 2. 当前代码基线和迁移目的

目标仓库现有 src/Trajectory.hpp 含前向匀速平移与绕选定轴的纯旋转；src/Room.hpp 含长方体房间离散网格；src/main.cpp 可生成单目图像、IMU、运动真值与 EuRoC 风格目录。其 IMU 生成、相机和 CSV 导出耦合于命令行入口，尚无独立可安装的 .so 或 cam1 数据通路。根目录有 Windows 构建预设、PowerShell 脚本和 Windows 文档。

来源仓库 src/VisualSim/Camera.hpp、StereoRig.hpp、Path.hpp、Room.hpp、MeshPlot.hpp、VisualSim.cpp 等具有双目、分段运动、场景渲染和批量 IMU 生成思路，但现有畸变系数多为零值占位、IMU 噪声尚未实际注入、时间运动学以浮点秒计算且 CMake 与 ROS 依赖耦合。**这些内容只能经审查迁移，不能把占位实现误认为已满足本需求。**

| 迁移方向 | 需求 |
| --- | --- |
| 保留目标现有能力 | 两种轨迹、房间场景、原有数据集导出与测试的有效行为 |
| 吸收来源新能力 | 左右相机、双目几何与渲染、静止/加速/圆周分段轨迹、参数格式、IMU 合成思路 |
| 在目标新增/修复 | 安装式共享库、无 ROS API、参数实时生效、实际畸变与 IMU 噪声、纳秒门控、查询缓存、解析几何求交 |
| 明确不迁移 | ROS 节点/消息/发布器、VIO/ESKF 求解器、预积分与评估逻辑（除非被独立仿真功能证明确实需要） |

## 3. 功能需求

### FR-01 构建、安装及独立使用

1. 在 Ubuntu 24.04 将 VisualSim 编译为 Linux 共享库（.so），可由其他 C++ 程序直接调用。
2. 支持用户指定安装前缀；安装库、公开头文件、CMake 导出目标及必要资源；外部工程无需引用源码目录即可 find_package、链接和运行。
3. 不依赖 ROS 安装、运行时环境变量、ROS 包类型或 ROS 节点；不能将 ROS 间接依赖藏于公共头文件。
4. 保留现有命令行生成器及有效数据集格式，改为复用同一仿真核心；禁止在库初始化、采样和查询时隐式创建、删除或覆盖数据目录。
5. Windows 平台配置必须明确失败；清理 Windows 专用预设和指令。不得因 Linux 目标而调低现有可用工具链版本。

### FR-02 解析轨迹及真实运动状态

1. 调用者可以设置轨迹，即在有效时间区间内，**位置和朝向关于时间的解析规律**；既支持内建轨迹，也支持调用者自定义解析轨迹。
2. 轨迹必须可给出同一时刻的当前位置、朝向、线速度、角速度、线加速度、角加速度。各物理量必须属于同一条几何/运动学一致的轨迹，不允许彼此矛盾的独立赋值悄悄生效。
3. 内建轨迹至少覆盖静止、匀速直线、匀加速直线、定轴匀速纯旋转、匀速圆周（可指定相机朝向规律）及有限段拼接。保留目标仓库现有轨迹含义；迁移来源仓库中可复用的分段机制。
4. 明确世界系 W、载体系 B、相机系 C、IMU 系 S 的方向约定以及各导数的表达坐标系；相机与 IMU 从同一真值运动状态采样。
5. 未定义时间/无效轨迹不允许被静默截断、外推或夹紧为边界位姿，除非调用者显式选用了允许此行为的轨迹模型。

### FR-03 传感器参数设置、读取及真实参与仿真

1. 可分别设置/读取 cam0、cam1 的图像尺寸、采样频率元数据、内参、外参、畸变模型和系数；至少实现针孔 + radial-tangential 畸变，明确系数顺序。
2. 可设置/读取 imu0 的外参、标称采样频率、陀螺仪/加速度计白噪声密度及零偏随机游走参数；必要时支持初始零偏、固定随机种子及是否启用噪声。
3. **每次成功修改参数后，后续传感器数据必须使用新的参数参与真实计算**。内参和畸变改变成像位置；外参改变左右目视图及 IMU 测量；噪声开关启用时由所设参数决定实际噪声统计特性。不得仅更新 getter/YAML 而继续用旧常量生成数据。
4. 默认 IMU 噪声关闭，输出无噪值；噪声开启时白噪声和偏置随机游走均应实际注入，支持设置种子复现。仅在关闭加噪模式时，噪声系数不改变无噪输出，此条件必须显式说明。
5. setter 必须验证合法性（有限数、正确维度与旋转、非负噪声、正采样率等）。配置变更后不得用过期位姿/标定解释历史图像；默认立即使相关图像缓存失效，旧时间戳查询应明确报错。

### FR-04 纳秒类型及时间语义

1. **凡属于纳秒的输入/输出时间、时间间隔、内部时间记录及缓存键，必须是 std::int64_t 的同一类型**；允许集中别名 TimestampNs = std::int64_t，并以编译期断言检查一致性。
2. 仿真零点为时间戳 0 ns。轨迹运算可在清晰边界将纳秒相对时间转换为 double 秒，但不得通过 double 秒回转生成原始时间戳或缓存键；检查范围及差分溢出。
3. 传感器输出采用调用者驱动：给定某个纳秒时刻，最多为每个开启的传感器生成一帧；**不**自动补发两个相机时间之间的全部 IMU 帧。
4. **禁止重复时间生成新帧。** 每个传感器独立要求新生成时间严格大于该传感器上一次成功生成时间：相等返回 DuplicateTimestamp，更早返回 OutOfOrderTimestamp。拒绝时不得产生新帧、消耗帧号、推进噪声状态或更改缓存。
5. 已在某时刻生成 cam0/cam1 后，允许同一时刻仅为此前未在该时刻生成的 imu0 输出数据；反之亦然。双目作为不可拆分的一组输出。
6. 显式 reset/new session 后才允许重新从旧时间开始采样；reset 的副作用及边界必须公开。

### FR-05 传感器门控与帧结构

输入为 std::int64_t timestamp_ns 及 stereo、imu 两个布尔门控：

| stereo | imu | 输出 |
| --- | --- | --- |
| false | false | 空结果，无副作用 |
| true | false | 同一时刻 cam0 和 cam1 两帧 |
| false | true | 该时刻 imu0 一帧 |
| true | true | 同一时刻 cam0、cam1、imu0 三帧 |

每个帧包含原始整数纳秒时间戳、传感器名称、传感器本地帧编号、传感器数据（图像或 IMU）。cam0、cam1、imu0 独立自 0 编号；左右目每次成对输出时编号一致；仅成功输出时递增。输出须规定图像尺寸、像素格式、数据所有权和生命周期，IMU 角速度单位 rad/s、加速度计比力单位 m/s²，以及坐标系。无效门控组合、越界时间或任何单个启用传感器重复/回退时，**整批原子失败**，不允许部分成功后留下状态。

### FR-06 最近图像位姿缓存

每个模拟器实例在内存中缓存最近成功生成的 **64 组双目图像位姿**（默认容量可配置），缓存键是（传感器名称，std::int64_t 时间戳）。每组保存左右目在世界系中的光心/旋转和关联的配置/场景版本或快照，以保证与实际生成时一致。IMU-only、全部门控关闭或失败调用不添加图像缓存。逐组 FIFO/LRU 淘汰策略应确定并记录；缓存未命中必须报错，不允许悄悄查询“最近的其他时刻”。

### FR-07 单位视线对应的真实世界交点

接口接收（图像时间戳 std::int64_t、单位视线 std::vector<Eigen::Vector3d>、相机标识，默认 cam0），返回与输入视线索引可对应的命中列表：世界坐标（米）、沿射线正向距离（米）、命中面标识及有效/失败状态。

- 输入视线在所选相机坐标系内表达；以该图像的**缓存位姿**变换到世界系；不重新按时间推算一个可能不同的位姿。
- “真实路标点”特指射线首次击中的**实际仿真场景可见表面点**，可以是连续面上的任意点，而不要求正好是绘制网格顶点；不得把估计深度/三角化结果混同为真值。
- 首要场景为长方体房间的四墙、地面、天花板：与六个有边界的面解析求交，过滤平行、背后、越界与无效视域，并选择最近有效正向交点；处理角点/棱边平局。
- 其他场景（如现有的三深度稀疏路标场）须有与渲染一致的明确可碰撞几何/可见性模型；若不具备，不得伪造连续交点。交点查询须在所有对外宣称支持真实查询的场景上有效。
- 非单位/非有限视线、视域外、无命中、缓存失效分别报告；保持列表输入顺序或携带原始索引，不能静默丢弃而造成错位。
- 查询只读，不产生传感器帧、帧号、随机扰动或时间推进。

### FR-08 输出、复现与安全性

1. 同一配置、解析轨迹、输入时间序列及随机种子下输出可复现；不同实例状态独立。
2. 传感器返回数据由调用者可安全持有；不得把内部临时 cv::Mat 内存或不稳定引用交给调用者。
3. 原有数据集输出及新双目输出可复用库接口显式导出，保留现有两个场景；写盘须由调用者主动触发，禁止自动删除任意用户目录。
4. 明确单实例线程安全规则。默认同实例串行读写/采样，允许多实例相互独立；如需并发则外部同步或在实现中扩展。
5. 未定义传感器、非法标定/轨迹、纳秒溢出、重复/回退时间、场景无命中与缓存未命中都应有明确可诊断的失败结果。

## 4. 验收标准

| ID | 验收内容 |
| --- | --- |
| AC-01 | Ubuntu 24.04 使用现有可用工具链构建、指定前缀安装、独立 CMake 工程链接并运行 .so；无需 ROS |
| AC-02 | Windows CMake 配置被明确拒绝；不再存在有效 Windows 构建预设或运行指令 |
| AC-03 | 旧前向平移/纯旋转与新静止/加速/圆周/组合解析轨迹返回的姿态、速度、加速度、角速度、角加速度互相一致 |
| AC-04 | 设置 cam0/cam1 内外参或非零畸变后，对应图像/几何响应变化且 getter 返回生效值 |
| AC-05 | 设置 IMU 外参后测量按正确坐标系变化；启用噪声时统计参数生效、固定种子可复现，关闭时无噪 |
| AC-06 | 四种门控组合输出正确，双目同步，三传感器帧号独立；纳秒字段全为 std::int64_t |
| AC-07 | 重复/回退的每传感器时间拒绝且整批无副作用；同刻不同传感器可分别生成；reset 可以重开会话 |
| AC-08 | 最近 64 组双目位姿按时间和相机精确匹配；淘汰、无效配置、查询不存在帧明确失败 |
| AC-09 | 已知射线与房间六面的交点解析正确；最邻近可见面、角点、无命中、畸变视域均有检查 |
| AC-10 | 返回内存所有权安全；保留原有两个 CLI 场景和 EuRoC 风格导出，且无隐式文件覆盖 |
| AC-11 | 目标仓库承接迁移代码、来源仓库未发生任何写操作；公共头文件及库依赖图不包含 ROS |

## 5. 交付边界与顺序

设计阶段交付 docs/SRS.md、docs/HLD.md、docs/LLD.md。实现阶段按“独立库/构建 → 轨迹与场景迁移 → 双目与标定 → IMU 与噪声 → 缓存/真实求交 → CLI 迁移与验收”的顺序完成；每个阶段均在**目标仓库**进行。不得把计划文档的存在误写为代码已经实现或测试已经通过。
