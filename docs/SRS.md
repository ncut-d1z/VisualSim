# VisualSim 运行时库需求分析（SRS）

> 本文只描述最终产品的功能、可观察行为和验收结果。不包含源码迁移表、实现过程、架构模块、求交算法或实施安排。技术方案见 [HLD.md](HLD.md)、[LLD.md](LLD.md)，实施任务见 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)。
>
> 目标产品：https://github.com/ncut-d1z/VisualSim 。

## 1. 产品目标与平台要求

VisualSim 应成为可安装、可由外部 C++ 程序通过函数调用或配置文件驱动的仿真运行时库。调用者可以按时间定义运动模式、运动参数和传感器标定，并在指定时间得到相应的运动真值、相机图像、IMU 观测及单位视线在真实场景表面的交点。

- 唯一目标平台为 Ubuntu 24.04；应支持共享库构建、指定安装前缀和独立 C++ 工程调用。
- 不依赖 ROS/ROS 2；允许使用 Eigen、Sophus、OpenCV 等与 ROS 无关的第三方库。
- **不再支持 Windows 编译**。
- 不要求降低用户现有能够编译相关项目的编译器、CMake、C++ 标准或第三方库版本。
- 轨迹由调用者函数调用或配置文件定义，不能只允许执行编译期硬编码的演示轨迹。
- 保留按需导出数据集的能力，但采样、求交等库调用不得隐式写盘或删除文件。

### 1.1 术语与符号

| 术语 | 含义 |
| --- | --- |
| W / B / C / S | 世界坐标系 / 载体坐标系 / 某台相机坐标系 / IMU 传感器坐标系 |
| T_BC、T_BS | 分别将相机 C、IMU S 的坐标转换至载体 B 的刚体变换；旋转和平移均按此方向定义 |
| camX | 相机自动名称，X 从 0 递增；传感器身份不因改名而改变 |
| 线/角模式 | 对位置变化、朝向变化独立生效的两类解析规律，各类同一时刻至多一种模式 |
| 运动作用域 | BeginMotionMode 与 EndMotionEnd 配对形成的嵌套模式保存与恢复范围 |
| 事件历史 | 调用者带生效时间戳提交的运动、传感器、Room 配置变更序列 |
| TimestampNs | 纳秒时间统一类型 std::int64_t；仿真原点记为 0 ns |
| 有效时间 | 被初始化的轨迹与场景模型能够提供确定真值的时间范围 |
| 传感器门控 | 每次请求是否输出全部当时存在的相机及/或 IMU 数据的独立开关 |

### 1.2 假设、外部依赖与范围外

假设调用者提供合法、有序且可追溯的运动/标定变更事件；相机与载体、IMU 与载体之间按刚性安装关系建模；Room 由四面墙、地板及天花板构成。所有相机均采用统一的世界坐标约定；加速度与噪声单位必须在公开接口明确。

允许的第三方依赖限于与 ROS 无关且为实现相关功能实际需要的库，例如 Eigen、Sophus、OpenCV、yaml-cpp；具体使用与版本要求属于设计/部署内容，不是本 SRS 规定的“必须采用”清单。目标平台 Ubuntu 24.04，已具备可用工具链。

**范围外**：ROS 节点和消息、Windows 可执行程序、ForwardDepthScene 及其他场景、固定只支持双目、传感器物理硬件驱动、隐式后台采样、任意同类模式并行叠加、未定义的非匀速角运动类型、未经授权缓存历史图像/位姿/IMU 样本/交点，以及没有明确调用授权时的数据写盘。

## 2. 两类运动模式及即时式调用

### FR-M01 两个独立运动类别

同时存在一个线运动类别和一个角运动类别。各类别具有以下互斥的当前模式：

| 类别 | 允许的模式 | 定义 |
| --- | --- | --- |
| 线运动 | 静止 | 位置不随时间改变 |
| 线运动 | 匀速直线运动 | 按指定恒定线速度运动 |
| 线运动 | 匀加速直线运动 | 按指定恒定线加速度运动 |
| 线运动 | 匀速圆周运动 | 按指定圆心、半径、轨道平面、相位和恒定速率运动 |
| 角运动 | 静止 | 朝向不随时间改变 |
| 角运动 | 定轴匀速纯旋转 | 按指定旋转轴和恒定角速率改变朝向 |

线运动的静止和角运动的静止是不同模式。**不允许类内并行组合**：同一时刻不能同时处于匀速直线和匀加速直线模式，也不能同时处于两种角模式。设置新的同类模式，必须**覆盖该类当前模式及相应参数**；不同类保持独立，可以跨类组合。例如“匀速直线 + 定轴匀速纯旋转”“匀速圆周 + 定轴匀速纯旋转”“线静止 + 角旋转”。

匀速圆周模式必须能够**显式指定世界圆心、半径、轨道平面、初始相位及角速率**，且首次生效时该圆周须与已经确定的当前位置相容；不相容的配置应明确拒绝。被运动作用域恢复时，应允许调用者在“保留原世界圆心（不相容则拒绝）”与“保留圆周形状和相位、以当前连续位置重新确定有效圆心”两种行为中明确选择；不能无声忽略已给定的圆心或导致非显式位置跳变。

### FR-M02 BeginMotionMode 与 EndMotionEnd

公共接口必须提供名称为 **BeginMotionMode** 和 **EndMotionEnd** 的函数，使用顺序式调用表达类似早期 OpenGL Immediate Mode 的运动定义。

- BeginMotionMode：在指定生效时间开启新作用域，把进入作用域前的线运动、角运动模式及参数保留为作用域的恢复目标。
- 作用域内调用参数/模式设置函数时，新的线运动模式仅覆盖当前线运动，新的角运动模式仅覆盖当前角运动，两类互不排斥。
- EndMotionEnd：在指定生效时间结束最近一个尚未结束的作用域，按照后进先出规则恢复进入该作用域前保存的模式和参数。
- 允许多层嵌套；不匹配的出栈必须报错。
- 正常入栈、覆盖和出栈**不使物体位置或朝向突然跳回旧状态**；恢复旧模式是从出栈时的当前位置、朝向继续按原参数运动。只有显式修改绝对位置/朝向才可能产生有意的跳变。

### FR-M03 时间戳与历史轨迹

每次设置初始位置、朝向、运动模式及运动参数，或者调用 BeginMotionMode、EndMotionEnd，均带有生效的纳秒时间戳。系统必须保存所设置的值和它们各次变更的时间戳、先后顺序与必要作用域关系，并能查询修改历史。

调用者在不同时刻连续改变运动参数后，任意时间 t 的位置和朝向应是从起点至 t 之间**所有有效时间段的解析运动累计结果**，包括每个改变时刻之前已经产生的位移与旋转。禁止仅套用最后一段运动而丢失此前结果。

可以无副作用地反复查询任意有效时刻（包括过去和未来）的真实运动状态。同一时间戳发生多个修改时，其执行顺序必须明确、可复现。函数调用和配置文件输入同一事件序列时应得到一致结果。

### FR-M04 可设置与可查询的物理量

调用者应能定义当前/初始位置、朝向、以及当前模式所允许的线速度、线加速度、角速度、**圆周显式圆心、半径、轨道平面法向、相位参考方向、初始相位、速率及恢复行为**等运动参数。按时间查询时至少能获得：位置、朝向、线速度、线加速度、角速度、角加速度。各量须有明确坐标系、单位、有效区间，并与对应的解析运动规律一致。

本版**角运动仅有“角静止”和“定轴匀速纯旋转”两种模式**，因此其非模式切换时刻的角加速度为零。如果调用者指定与当前模式矛盾的非零角加速度，必须明确拒绝，不能存下后忽略。非零角加速度需通过另行扩展角运动模式支持。

## 3. 动态相机注册和传感器标定

### FR-S01 不限制相机数量

相机不固定为单目或双目。调用者提供新相机的外参并要求创建相机时，系统自动增加相机并赋予依次递增的默认名称 cam0、cam1、cam2……；编号从 0 开始。调用者可在指定生效时间修改任一相机的名称；有效名称不得重复，并且不同相机的身份不能因重命名而混淆。

若调用者尚未调用相机创建函数，必须有**一台且仅有一台**默认相机，其名称为 cam0，外参为 \((I_3,\mathbf 0)\)，即没有相对旋转和平移。仅输入新相机外参进行注册时，应自动赋予该相机**完整有效的默认内参、分辨率、零畸变参数和标称采样率**，且这些默认值必须与实际生成图像和标定读取接口一致，无需调用者再设置一次标定才能生成图像。

**在仿真起点 t=0 首次显式创建相机**时，只有此前没有针对默认 cam0 的标定、改名等显式配置事件、也未生成相机帧，首台显式相机才能占用 cam0 并替代未使用的默认配置。若默认 cam0 已被修改或实际使用，应**保留该相机的身份和所有修改历史**，新增相机分配后续 camX；**在 t>0 首次创建**时，t=0 已存在的默认 cam0 应保留。自动分配名称不得覆盖其他相机；若某个候选 camX 已被重命名占用，则应跳过冲突名称，继续分配可用的后续编号，且不能回收曾自动分配过的编号。

每台相机拥有独立的内参、外参、图像分辨率、畸变模型/系数等。指定时间能获取该时刻存在的相机及当时有效的名称。

### FR-S02 参数设置、获取及真实生效

调用者可以按指定生效时间设置和读取每台相机的内参、外参、畸变及 IMU 的外参、白噪声密度、零偏随机游走等标定参数。

- 改变相机参数必须**实际改变该时刻起的成像计算**，而不是只更新 getter、YAML 或日志。
- 改变 IMU 外参必须实际改变输出的角速度、比力，以及适用时的杆臂效应。v1 的重力取固定世界向量 \(\mathbf g_W=(0,0,-9.81)\ \mathrm{m/s^2}\)，必须参与 IMU 比力仿真；本版不提供改变重力的配置操作。
- IMU 默认关闭随机加噪；启用后必须使用配置的噪声参数参与真实采样，并支持固定随机种子复现。
- 根据历史时刻查询数据时，必须应用**当时生效**的参数，而非最新参数。
- 参数设置无效、相机名称冲突、传感器不存在等情况须有明确错误，不得部分生效。

### FR-S03 时间与传感器门控

每次采样由调用者输入纳秒时间、camera 门控和 imu 门控。camera 门控控制**当时存在的所有相机**，不是固定 cam0/cam1 两台。

| camera | imu | 本次结果 |
| --- | --- | --- |
| 关闭 | 关闭 | 不产生帧 |
| 开启 | 关闭 | 当前所有相机各一帧 |
| 关闭 | 开启 | imu0 一帧 |
| 开启 | 开启 | 当前所有相机各一帧，外加 imu0 一帧 |

每个帧包括原始纳秒时间、传感器名称、该传感器自己的帧编号和图像/IMU 数据。相机同批次时间戳相同。帧编号从 0 开始，逐传感器独立编号；相机名称可变但传感器身份及其编号连续性不因改名而重置。

**同一传感器时间必须严格递增。** 对同一传感器重复已有成功生成的时间，须拒绝生成新帧；回退到更早时间亦拒绝。不同传感器可以在同一时间分别生成。一个调用中只要任何启用传感器不合法，整个调用不得产生部分结果、消耗帧号或错误推进状态。需要重新从早期时间开始采样时，必须显式开启新会话或重置。

## 4. 场景与几何查询

### FR-G01 Room 是唯一场景

系统只有 **Room 长方体房间**场景，包含四面墙壁、地板及天花板，支持设置房间尺寸与必要几何参数。所有相机图像均以 Room 为场景基础。不提供 ForwardDepthScene，也不依赖其他场景模式。

### FR-G02 任意时刻的视线真实交点

调用者输入以下数据：查询时间（纳秒）、相机名称（省略时默认 cam0）、相机坐标系下的单位视线向量列表（std::vector 容器）。

结果应与输入视线保持可追溯的一一对应；每条有效视线返回在该查询时间的相机位姿下，与 Room 有效可见表面**最近的正向交点**的世界坐标（米）。无命中、非法视线、超出视域、相机在该时刻不存在等情形须有明确状态。**输入视线为空时，只要时间和相机合法，应成功返回空结果；时间或相机无效仍报告对应的整体错误**。

**不要求指定时刻曾经生成过图像。** 可以直接查询任意有效时间的交点；反复查询不得改变运动、传感器帧号或修改历史。不得通过固定帧位姿缓存来限制查询时间范围。

## 5. 历史记录与存储范围

### FR-C01 必须保存的持久业务状态

必须保存当前有效的线/角运动模式、模式参数、运动作用域，以及当前相机/IMU/Room 配置；并保存调用者对这些变量**每次修改的记录**，至少包括：

- 生效时间戳；
- 修改目标及新的模式/参数值；
- 同时间戳的确定性操作顺序；
- 作用域入栈/出栈、相机创建/改名和标定更改等必要关系。

读取这些记录后，系统应能还原任意有效时间的运动状态和传感器几何。

### FR-C02 不需要也不得建立的额外数据缓存

**除运动模式、运动参数、传感器及 Room 配置和它们的时间戳修改历史之外，不得建立历史数据缓存。** 不应缓存已生成图像、IMU 帧、按帧位姿、射线交点或重算后的轨迹中间结果。历史查询时基于记录重新计算。

为满足唯一帧编号和禁止重复时间而必需的每传感器轻量控制状态（最近一次成功生成的时间和下一帧编号）是接口控制变量，不是保存历史帧的数据缓存。它不能扩展成历史采样结果存储。

## 6. 外部接口需求概览

下表规定对外可用的**能力类别、信息输入输出和失败类型**，不是强制某一编程语言签名；冻结的 C++ 签名见 LLD。全部以纳秒表示的时间字段均为 std::int64_t。

| 能力 | 主要输入 | 主要输出 | 失败类别 |
| --- | --- | --- | --- |
| BeginMotionMode / EndMotionEnd | 生效时间 | 作用域变更结果 | 时间顺序、栈不匹配、历史冻结 |
| 运动模式/参数及绝对位姿设置 | 生效时间、线/角模式和参数或位姿 | 当前配置及历史记录 | 不合法物理量、模式冲突、事件时序 |
| 创建相机 / 重命名相机 | 生效时间、外参、可选新名 | 稳定相机身份和当前名称 | 重名、非法外参、非法生效时间 |
| 设置/读取标定与 Room | 传感器身份、有效时间、参数 | 对应时刻有效配置 | 未注册传感器、无效参数 |
| 查询历史/运动真值 | 指定时间；历史记录可选纳秒起止闭区间 | 全部/指定闭区间的变更记录，或该时刻六项运动真值 | 非法时间区间、时间越界、模型不可求值 |
| Generate | 纳秒时间、camera / imu 门控 | 0 至 N+1 个传感器帧及其编号 | 时间重复/回退、标定无效、整批生成失败 |
| Raycast | 纳秒时间、相机、std::vector 单位视线 | 对应顺序的世界坐标命中或逐条失败状态 | 相机不存在、非法方向、无表面命中 |
| LoadMotionConfig | 配置文件路径及内容 | 与函数调用等价的事件历史 | schema、参数、时间、作用域或文件错误 |
| ResetSamplingSession | 显式会话重置请求 | 重新允许按新序列生成，原参数与历史继续有效 | 状态不一致、重置执行失败 |

外部接口须允许调用者以程序化状态识别错误，而不要求解析日志文本；任何失败不能留下已提交一半的配置/传感器帧。数据所有权和并发使用限制须由公开 API 文档说明。

## 7. 纳秒、复现及安装

- **所有纳秒时间参数、变更记录时间戳、生成帧时间戳和以纳秒定义的时间间隔均为 std::int64_t**，且不得经浮点秒往返而改变原始值。
- 修改历史不得因之后的操作而默默重写已经成功生成的传感器帧所对应的历史配置。
- 相同初始条件、修改历史、采样请求与随机种子应产生可复现的结果。
- 外部调用者可安全持有返回的数据；必须有明确的坐标系、单位、生命周期及错误说明。
- 相同的函数调用和配置文件定义应可重现静止、直线、圆周、纯旋转和跨类组合运动及数据集输出。

## 8. 非功能需求（NFR）

| 编号 | 质量属性及可检查要求 |
| --- | --- |
| NFR-01 | **持久状态上界**：系统持久保留的数据仅随变更事件数量、传感器注册数量和必要的最小帧计数控制量增长；重复只读求交或采样完成后，不能累积历史计算结果对象。通过状态结构审查及多轮查询前后驻留状态检查核验。 |
| NFR-02 | **性能可测量，验收延期**：保留未来测量 Generate、Raycast、运动真值查询的延迟分布、峰值内存和重放工作量的能力。首次成功运行程序并生成有效传感器数据之后，再视实测结果考虑性能预算与正式性能验收；**不作为目前代码开发、编译、功能验证的阻断条件**。 |
| NFR-03 | **线程安全和多实例**：多个实例的事件、传感器编号与种子相互隔离；同一实例的跨线程调用规则必须公开声明并通过并发用例检查。 |
| NFR-04 | **故障恢复/原子性**：任何不合法事件、冲突标定、重复/回退生成或批次生成失败不得改变已提交的事件序列、编号和有效参数。 |
| NFR-05 | **可观测性**：所有可预见失败须提供稳定、可编程识别的错误类别及可选诊断消息；正常运行不要求打开 GUI、读取 ROS 环境或写文件。 |
| NFR-06 | **安装和二进制边界**：通过指定前缀安装后可由独立 CMake 消费者链接、运行；对外明确所需 ABI/编译环境，不能默许跨不同编译器/第三方库版本的二进制兼容。 |
| NFR-07 | **复现与数值正确性**：同一工具链、场景、时间戳事件序列和随机种子下重复生成有确定性；计算的运动/投影/射线与解析参考结果在明确的数值容差下吻合，容差由详细设计和测试说明给出。 |

**性能验收已明确延期**：首次成功运行程序并生成有效数据前，不设 P95/P99 延迟和峰值内存验收预算；其后再根据数据考虑是否开展正式性能验收。ABI 仅承诺已定义的兼容构建环境，不承诺跨工具链长期二进制兼容；当前无需额外人工决策。
