# VisualSim 文档审计规范（AUDIT）

> 适用对象：目标仓库 ncut-d1z/VisualSim 的 docs/SRS.md、docs/HLD.md、docs/LLD.md、docs/IMPLEMENTATION_PLAN.md。审计依据参考 ISO/IEC/IEEE 29148 的需求规格思想与 IEEE 1016 的设计描述思想，**不是标准逐条认证**。本文件与 [AUDIT_PROGRESS.md](AUDIT_PROGRESS.md) 一同管理审计与整改。
>
> 只允许写入 ncut-d1z/VisualSim 的文档；ncut-d1z/ros2-vio-node 为只读迁移来源，禁止修改。未经明确要求不修改源码、编译、CTest 或运行仿真。

## 1. 评审结论与必须保留的优势

初始人工评审认为：四份文档结构较清楚、相互引用、仓库边界和关键产品决定基本一致；但**不具备严格冻结实施基线所需的完整度**。SRS 基本符合但缺 NFR/接口/术语/追踪；HLD 具有模块架构但层级混合，缺接口/权衡；LLD 接口与算法丰富但许多合同待冻结；IMPLEMENTATION_PLAN 作为实施计划合适但风险/排期/检查清单不完整。

**审计和整改必须保留**：Ubuntu 24.04 Linux-only、不可降低既有可用工具链、无 ROS、Room 唯一场景、禁止历史计算结果缓存（包括位姿/帧/交点）、基于时间戳记录的即时式运动模式、BeginMotionMode 与 EndMotionEnd、线/角类内互斥与跨类组合、动态 cam0..camN 与重命名、纳秒 std::int64_t、传感器同类时间严格递增、整批失败回滚、标定真实参与仿真、来源仓库只读。不得为了追求文档“完整”改写这些已获用户批准的需求。

## 3. 审计操作和整改证据规则

1. **先登记再审计**：将人工意见的每个目标编号写入本文件和 AUDIT_PROGRESS.md，初始文件审计状态为“未审计”，目标整改状态为“未整改”，不得预先标为已审计/已整改。
2. 文件审计状态：**未审计 / 正在审计 / 已审计**。状态“已审计”只表示按规则核查并记录发现，不表示问题已整改或实现已验证。
3. 每项目标整改状态：**未整改 / 整改中 / 已整改 / 待人类决策**。变更“已整改”须给出修改后的**具体文档章节或链接**、该目标的验收依据；仅增加 TODO 不算解决。
4. 审计流程：基于最新 main 逐文件比对用户意见和实际文本→记录发现/证据/严重性→核对跨文档一致性→按 SRS→HLD→LLD→PLAN 层级整改→复扫所有受影响文件→在进度文件记录结果和提交 SHA。
5. 对确实需要人类确定的性能阈值、ABI 兼容承诺、具体时间/负责人等，**不得编造**；明确列为“待人类决策”，同时可先完成不依赖这些数字的结构整改。
6. 不得通过把尚未定稿的合同伪称“已冻结”来关闭问题。LLD 的模式/参数/边界规则如有互相冲突，必须具体标记并给出方案或决策入口。
7. 每次更新进度应报告：审计完成文件数/总数、各类整改状态项数/总数、未整改或待决具体 ID、对应提交；避免把文档审核、代码完成、测试通过混为一谈。
8. 对已经满足的用户意见仍需登记“已核验，无修改”，并提供定位证据；不能漏掉人工意见中的某一条。
9. 追踪矩阵最少涵盖 **FR / NFR / AC → LLD 接口或算法 → V 用例 → P 阶段**；不存在自然对应时标“无/待补”，不能伪造已实现。
10. 适用的限制：本轮只读第一个仓库；全部整改文档仅提交第二个仓库 docs/；不得提交来源仓库任何文件。

## 5. 特殊核验点

- 对 SRS-04：人工意见提到 “64 组缓存” 是**旧设计名称不应再作为现行要求**；SRS 应表达禁止缓存历史计算结果的业务需求，而不引入历史变更过程。
- 对 LLD-07：不仅要给示例 YAML，还应给生效时间、作用域、重复键、非法值、未来相机、报错和全部提交/回滚的确切规则；IMU 噪声需定义密度单位、离散化、时间驱动和随机过程可复现的边界。
- 对 PLAN-03：排期、负责人以及性能基准未获授权时可以写“待定 / 未指定”，但必须指明下一次决策/基准测试触发条件，不应随意指定日期、人数、CI 系统或性能数字。
- 对 HLD-01：HLD 可以保留**为何**采用事件历史/按需重算的高层决策，不能重复 LLD 的精确入栈、求交和门控伪代码。
- 保护已做好的优势与约束，保证跨文档不出现“仅双目”“先生成图像才能求交”“可重复生成相同传感器时间”或 ForwardDepthScene 等已撤回内容。

## 6. 完成标准

**审计完成**：4/4 文档按本规范核查，28/28 目标有结论和证据，发现与整改状态一致，跨文档再扫描完成。

**整改完成**：所有可确定的目标均实际修改且复核通过；凡需人类输入的项保留“待人类决策”，不能冒充完成。在已获批准的所有量化验收门槛明确前，整体状态最多为“条件性设计基线”，不能称“严格冻结可直接实施”。

**代码状态独立**：所有这些文档完成不代表源码修改、编译或实测验收通过。
